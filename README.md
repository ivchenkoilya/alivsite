# ALIV SPORT — редизайн (фронтенд-прототип на реальных данных)

Полный редизайн публичной части сайта https://alivsport.inetsystems.ru/ в стиле
**Premium Industrial / Performance Luxury** по пяти референсам из `references/`.

## Что это и чем не является

Текущий сайт — **WordPress 7.1 + WooCommerce 9.8 + тема Woodmart + Elementor + Contact Form 7**.
Исходников темы и доступа к админке в этой работе не было, поэтому редизайн сделан как
**самостоятельный статический фронтенд** (HTML/CSS/JS без фреймворков), который:

- использует **реальные данные** сайта — 55 товаров, цены, артикулы, характеристики, фото,
  категории (WooCommerce Store API) и прайс-лист на 219 позиций (страница `/prajs-list/`);
- отправляет заявки через **существующую форму Contact Form 7** (id 16) сайта;
- **не меняет** ничего на рабочем сайте: ни цены, ни заказы, ни настройки.

Это готовая дизайн-система и вёрстка всех ключевых экранов, которую следующим шагом нужно
перенести в дочернюю тему WordPress (см. «Перенос в WordPress»).

## Запуск

```bash
npm install            # только playwright-core для проверок (браузер берётся системный Chrome)
npm run build          # src/ + assets/ + data/ → dist/
npm run serve          # http://localhost:5173
node tools/e2e.js      # 66 сценариев: каталог, фильтры, товар, корзина, заказ, сравнение, конструктор, отзывы, прайс, формы, меню
node tools/screenshots.js                       # скриншоты 9 страниц × 7 ширин → qa/
node tools/overlays.js                          # состояния: меню, корзина, модалки, поиск, выпадающее меню → qa/ov/
node tools/audit.js                             # все ссылки ведут на существующие страницы, все кнопки что-то делают
node tools/screenshots.js index,catalog 390,1440  # выборочно
```

Обновить данные с рабочего сайта:

```bash
# скачать в любую папку RAW:
#   /wp-json/wc/store/v1/products?per_page=100           → RAW/p1.json
#   /wp-json/wc/store/v1/products/categories?per_page=100 → RAW/cats.json
#   /wp-json/wp/v2/pages?per_page=100&_fields=slug,content → RAW/pagesc.json
node tools/build-data.js RAW && npm run build
```

## Бренд и «изюминки»

- Новый логотип: `assets/img/emblem.svg` + надпись ALIV SPORT в вёрстке (`src/partials/logo.html`). Старый логотип: `BRAND=original npm run build`.
- «Разбор модели» на главной (`assets/js/story.js`) — текст прокручивается как обычно, а фото рядом «наезжает» на деталь и перетекает в следующий кадр (анимация привязана к прокрутке). Кадры и точки фокуса — в `STORIES` внутри файла.
- Переход «карточка → страница товара» (View Transitions API, Chrome/Edge/Safari 18+; в остальных браузерах — обычный переход).
- Осмотр фото: клик — приближение в точку, колёсико/щипок — масштаб, перетаскивание — осмотр, клавиши + − 0.
- «Поместится ли в ваш зал?» на странице товара — план сверху по габаритам производителя.
- Бегущая строка реальных моделей, подсветка карточек под курсором, лёгкое «зерно» на фоне.

## Публикация на GitHub

1. Создайте пустой репозиторий на GitHub и загрузите в него содержимое архива (или `git init && git add . && git commit -m "ALIV SPORT redesign" && git push`).
2. В репозитории: **Settings → Pages → Source: GitHub Actions**.
3. Готово: при каждом изменении в ветке `main` workflow `.github/workflows/pages.yml` сам соберёт сайт (`node tools/build.js`) и опубликует его по адресу `https://<логин>.github.io/<репозиторий>/`.

На GitHub Pages формы работают в демо-режиме (настоящая отправка включается только на домене сайта — `assets/js/config.js → forms`).

## Что есть на сайте (кратко)

Главная (витрина тренажёров, «Тренажёры дня» с осмотром, серии с превью), каталог (фильтры, плитка/список, сравнение), карточка товара (галерея с лупой, «поместится ли», отзывы с модерацией, недавно смотрели), конструктор зала, сравнение, прайс-лист (карточка каждой позиции), о компании, контакты (звонок/почта работают и на компьютере), корзина, избранное, 404.

## Структура

```

src/partials/           общие header, footer, иконки (SVG-спрайт), модалки/дроверы
assets/css/tokens.css   дизайн-токены: цвета, типографика, отступы, радиусы, тени, анимации
assets/css/main.css     база и компоненты: кнопки, чипы, карточки, формы, модалки, тосты…
assets/css/pages.css    композиции главной, каталога, шапок страниц
assets/css/{product,about,price,contacts,cart}.css  стили отдельных страниц
assets/js/config.js     настройки: режим форм, пути к новым изображениям, контакты
assets/js/core.js       корзина, избранное, поиск, формы (CF7), модалки, анимации
assets/js/*.js          логика страниц
data/products.js        товары (генерируется tools/build-data.js)
data/pricelist.js       прайс-лист (генерируется)

IMAGE_REQUESTS.md       ТЗ на изображения для ChatGPT
```

## Формы

`assets/js/config.js → forms.mode`:

- `auto` (по умолчанию) — заявки реально уходят только на домене `alivsport.inetsystems.ru`,
  на localhost/стейджинге работает **демо-режим** (валидация, загрузка, сообщение «Демо-режим», без отправки);
- `live` — всегда отправлять через CF7 (`/wp-json/contact-form-7/v1/contact-forms/16/feedback`, поля `your-name`, `tel-774`, `your-message`);
- `demo` — никогда не отправлять.

Корзина и «оформление заказа» в прототипе формируют заявку с составом заказа и отправляют её
той же формой CF7. В WordPress-версии корзина и checkout должны остаться штатными WooCommerce.

## Перенос в WordPress (следующий этап)

1. Дочерняя тема от Woodmart (или отдельная тема) — **на копии сайта / стейджинге**, не на production.
2. Подключить `tokens.css`, `main.css` и стили страниц; шрифты Unbounded + Manrope (лучше локально).
3. Шаблоны WooCommerce: `archive-product.php` (каталог), `content-product.php` (карточка),
   `single-product.php` (товар) — разметка из `src/pages/catalog.html` / `product.html` и `core.js → productCard()`.
   Данные брать из WooCommerce, а не из `data/products.js`.
4. Фильтры: «Тип оборудования» и «Назначение» сейчас вычисляются из названия товара
   (`tools/build-data.js → TYPE_RULES`). В WP их нужно завести как атрибуты/метки товара.
5. Корзина/избранное: штатные WooCommerce cart + wishlist Woodmart; мини-корзина — через фрагменты Woo.
6. Формы — те же CF7 (id 16) или новые формы CF7 с полями email/город.
7. Страницы «О нас», «Прайс-лист», «Контакты», главная — шаблоны страниц; прайс-лист лучше
   хранить как CSV/ACF-репитер, чтобы выгрузка XLSX и таблица брали одни данные.
8. Сохранить URL: `/shop/`, `/product/<slug>/`, `/o-nas/`, `/prajs-list/`, `/kontakty/`, `/wishlist/`
   (в прототипе это `catalog.html`, `product.html?slug=`, `about.html`, `price.html`, `contacts.html`, `favorites.html`; canonical уже указывают на реальные URL).

## Известные ограничения прототипа

- Страница товара и каталог рендерятся на клиенте (JS); в WordPress это будет серверный рендер (лучше для SEO).
- Фото товаров подгружаются с рабочего сайта (`wp-content/uploads`) — отдельно не оптимизировались;
  `main-slide.jpg` весит ~1,1 МБ — для hero нужен WebP (см. IMAGE_REQUESTS №01).
- Мессенджеры (WhatsApp/Telegram/Viber) не добавлены: на текущем сайте нет подтверждённых аккаунтов.
- Документы к товарам не выводятся: плагин `woo-product-attachment` установлен, но через публичный API вложения не отдаются.
- Lighthouse не запускался; LCP/CLS измерялись в Chrome через Playwright (локально, без троттлинга).
